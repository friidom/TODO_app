## A · React и фронтенд

### `@/` — алиас пути
**Простое.** Короткий адрес вместо «поднимись на три папки вверх».
**Техническое.** Псевдоним модуля, который резолвер разворачивает в реальный путь.
**В Veylo.** `@/` → `src/`, объявлен **дважды**: в `vite.config.ts` (для сборки) и
в `tsconfig.app.json` (для компилятора). Забыть одно из двух — рабочий дев-сервер и
красный `npm run build`. Существующие импорты свободно мешают `@/` и относительные пути.

### Barrel (баррель)
**Простое.** `index.ts`, который пересобирает содержимое папки в один вход.
**Техническое.** Модуль-реэкспорт: `export * from "./a"`.
**В Veylo.** **Их нет** — сознательно. Компоненты импортируют хуки по прямому пути
(`@/services/todos/useAddTodo`). Барреля нет ни в одной папке `src/services/*`;
единственный `index.ts` — в `src/components/i18n/`.

### `cn()`
**Простое.** Склеивает классы и разруливает конфликты между ними.
**Техническое.** `clsx` собирает список, `tailwind-merge` убирает проигравшие
утилиты (последняя `p-2` побеждает раннюю `p-4`).
**В Veylo.** `src/utils/cn.ts`, пять строк: `twMerge(clsx(inputs))`.

### Collision detection (определение попадания)
**Простое.** Правило «над чем именно я сейчас держу карточку».
**Техническое.** Функция dnd-kit, получающая прямоугольники всех droppable и
возвращающая победителя.
**В Veylo.** `src/hooks/useKanbanDnd.ts` — **самописная**, и она игнорирует
пересечение прямоугольников: выбирает **щель, ближайшую к курсору**. Плюс отбрасывает
щель, соседи которой (`beforeId`/`afterId`) — сама перетаскиваемая карточка, иначе
индикатор предлагал бы бессмысленный дроп вокруг неё самой.

### Component (компонент)
**Простое.** Функция, которая возвращает кусок интерфейса.
**Техническое.** Функция, принимающая props и возвращающая React-элементы.
**В Veylo.** 111 `.tsx` в `src/components/`, сгруппированных по фиче:
`kanban/`, `columns/`, `timeline/`, `calendar/`, `members/`, `notifications/` и т. д.

### Context (контекст)
**Простое.** Ящик, из которого может читать любой потомок, минуя передачу через
props на каждом уровне.
**Техническое.** `createContext` + `Provider`; потребители перерисовываются при смене
значения.
**В Veylo.** Три: auth, тема, тосты. Значения контекстов лежат **в отдельных файлах**
(`providers/authContext.ts`, `providers/themeContext.ts`) — см. Fast Refresh.

### Design token (токен дизайна)
**Простое.** Именованный цвет вместо цифрового кода в разметке.
**Техническое.** CSS-переменная, зарегистрированная в системе тем.
**В Veylo.** `src/styles/global.css`: переменные вроде `--canvas` регистрируются в
блоке `@theme inline` (строка 252) как `--color-canvas`, после чего в разметке
доступен класс `bg-canvas`. Именно он стоит в `FeedList.tsx` на «липком» заголовке.

### DragOverlay
**Простое.** Копия карточки, которая летает за курсором.
**Техническое.** Компонент dnd-kit, рендерящий перетаскиваемый элемент вне потока
документа.
**В Veylo.** **Единственное, что двигается во время драга.** Доска под ним не
переливается: `@dnd-kit/sortable` не используется, карточки стоят на местах.

### DropZone
**Простое.** Невидимая полоска между карточками, которая умеет светиться.
**Техническое.** Всегда смонтированный droppable, живущий *между* элементами, а не на них.
**В Veylo.** `DropZone` / `ColumnDropZone` с идентификаторами
`todo-gap:<columnId>:<index>` и `column-gap:<index>`. Существуют, чтобы их можно было
**измерить**, и рисуют синюю линию, когда они — ближайшая щель. В покое `DropZone`
работает второй работой: наведение → `+` → форма создания задачи прямо в этой позиции.

### Error Boundary
**Простое.** Сетка, ловящая падение так, чтобы вниз улетел не весь экран.
**Техническое.** Компонент, перехватывающий исключения при рендере поддерева.
**В Veylo.** `src/components/ErrorBoundary.tsx` оборачивает список карточек **каждой
колонки отдельно** — одна битая карточка стоит своего списка и ничего больше. Внешняя
сетка — `errorElement` на каждом маршруте (`src/pages/error/RouteErrorPage.tsx`).

### Fast Refresh
**Простое.** Правка в файле меняет экран, не сбрасывая состояние.
**Техническое.** Горячая замена модулей, сохраняющая state компонентов.
**В Veylo.** Прямая причина того, что `authContext.ts` и `themeContext.ts` — отдельные
файлы: Fast Refresh **не может** обновить модуль, где компонент экспортируется вместе с
чем-то ещё. Архитектурное решение, продиктованное инструментом.

### Hook (хук)
**Простое.** Функция, дающая компоненту память и побочные эффекты.
**Техническое.** Функция с префиксом `use`, вызываемая безусловно и на верхнем уровне.
**В Veylo.** 19 модулей в `src/hooks/` плюс `use*.ts` внутри каждой папки
`src/services/*`.

### i18n
**Простое.** Один интерфейс на трёх языках.
**Техническое.** Подстановка строк по ключу для выбранной локали.
**В Veylo.** `src/components/i18n/` (en / ru / uz, язык в `localStorage`). Важное
правило: **названия колонок не переводятся никогда** — это пользовательский текст,
он идёт через `columnTitle()` как есть. Переводится *категория* колонки, через
`categoryLabelKey(category)` → `columnCategory.<category>`.

### Provider (провайдер)
**Простое.** Компонент, который кладёт значение в контекст для всех, кто внутри.
**Техническое.** `<Context.Provider value={…}>`.
**В Veylo.** `AuthProvider` смонтирован в `main.tsx` **выше** `QueryClientProvider` —
и поэтому импортирует `queryClient` как модуль напрямую: `useQueryClient()` на этой
высоте контекста ещё не видит.

### Sensor (сенсор)
**Простое.** Что считается началом перетаскивания — мышь, палец, клавиатура.
**Техническое.** Адаптер ввода dnd-kit, превращающий события в drag-события.
**В Veylo.** Настраиваются в `src/hooks/useKanbanDnd.ts`. Клавиатурный путь вынесен
отдельно: `src/hooks/keyboardDrag.ts` + `dragAnnouncements.ts` (объявления для
скринридера), у обоих есть тесты.

### Swimlane (дорожка)
**Простое.** Доска, разрезанная поперёк: по строке на исполнителя или на приоритет.
**Техническое.** Группировка карточек в горизонтальные полосы, каждая из которых
повторяет набор колонок.
**В Veylo.** `src/components/kanban/Swimlanes.tsx`, признак группы —
`isSwimlaneGroup` из `src/services/todos/view.ts`.

### Theme variant (вариант темы)
**Простое.** «Этот цвет — только в тёмной теме».
**Техническое.** Пользовательский вариант Tailwind, привязанный к селектору.
**В Veylo.** `src/styles/global.css:6` — `@custom-variant dark (&:where(.dark, .dark *))`,
класс `dark` вешает `ThemeProvider` на `<html>`. Рядом, строка 20, живёт
`@custom-variant coarse (@media (pointer: coarse))` — вариант «палец, а не мышь».

### View registry (реестр представлений)
**Простое.** Таблица «что каждое представление умеет».
**Техническое.** Возможности вида как **данные**, а не как условия в коде.
**В Veylo.** `src/services/views/registry.ts`: `VIEW_MODES` = summary, board, list,
calendar, timeline; у каждого `canReorder` / `canGroup` / `canSort`. До реестра
`useBoardView` выводил `dndDisabled` захардкоженным выражением, и ответ на вопрос
«пишет ли этот вид порядок» был code review, а не поиском в таблице.

### ViewMode
**Простое.** Название вкладки доски.
**Техническое.** Union-тип, выведенный из массива: `(typeof VIEW_MODES)[number]`.
**В Veylo.** Порядок в массиве — это порядок вкладок на экране. `summary` идёт первым,
но **не является** значением по умолчанию: `useBoardView` по-прежнему падает в `board`,
чтобы старые ссылки `/boards/:id` открывали ровно то, что открывали.

## B · TanStack Query

### `cancelQueries`
**Простое.** «Стоп, не перезаписывай кеш ответом, который уже в пути».
**Техническое.** Отмена активных запросов по ключу.
**В Veylo.** Первый шаг каждого `onMutate`. Из-за него `onMutate` **асинхронен**, и
именно поэтому `useColumnReorder` пишет кеш ещё и сам: запись из `onMutate` придёт на
тик позже.

### `enabled` (отключённый запрос)
**Простое.** Запрос, который ждёт, пока появятся данные для вопроса.
**Техническое.** Флаг, при `false` запрос не выполняется и остаётся `pending`.
**В Veylo.** Ключи вроде `queryKeys.todos(undefined)` — реальное состояние: параметр
маршрута ещё не разрешился. Запись в кеше есть, запрос выключен, ничего не грузится.

### `gcTime`
**Простое.** Сколько кеш хранит данные, которые никто не смотрит.
**Техническое.** Время до сборки мусора для неиспользуемой записи.
**В Veylo.** `10 * 60_000` — 10 минут, `src/services/queryClient/queryClient.ts:114`.

### `invalidateQueries`
**Простое.** «Эти данные устарели, перечитай».
**Техническое.** Пометить записи устаревшими и перезапросить активные.
**В Veylo.** Применяется точечно, **не** для перемещений карточек. Работает по
префиксу: `queryKeys.inviteeSearches(boardId)` покрывает все закешированные поиски
одной доски.

### `meta: { silent: true }`
**Простое.** «Про эту ошибку тост не показывай».
**Техническое.** Произвольные метаданные запроса, типизированные через
`Register`-augmentation.
**В Veylo.** `queryClient.ts:51` и `:89`. Штатный способ отказаться от центрального
тоста — вместо того чтобы добавлять свой `onError` в конкретную мутацию.

### Mutation (мутация)
**Простое.** Запрос, который меняет данные.
**Техническое.** `useMutation`: `mutationFn` + жизненный цикл `onMutate` → `onError`
→ `onSettled`.
**В Veylo.** Все в `src/services/*/use*.ts`. Ретраев у мутаций нет:
`retry: false`, `queryClient.ts:122`.

### MutationCache / QueryCache
**Простое.** Общий обработчик всех неудач сразу.
**Техническое.** Глобальные подписки на события кеша.
**В Veylo.** `MutationCache` тостит **любую** отклонённую мутацию. `QueryCache` тостит
только неудачный **повторный** запрос — провал первой загрузки уже нарисован
компонентом, который этим запросом владеет. Разница между «ничего не появилось» и
«то, что было, не обновилось».

### `onMutate`
**Простое.** «Нарисуй результат сразу, ответ придёт потом».
**Техническое.** Колбэк перед отправкой; его возвращаемое значение приходит в `onError`.
**В Veylo.** Канонический вид: `cancelQueries` → снимок → `setQueryData(apply*(…))` →
вернуть снимок для отката.

### Optimistic update (оптимистичное обновление)
**Простое.** Интерфейс верит, что получится, и не ждёт сервер.
**Техническое.** Локальная запись предполагаемого результата с откатом при ошибке.
**В Veylo.** Основной режим работы доски. Держится на том, что **`id` минтит клиент**
(`crypto.randomUUID()`): оптимистичная строка и сохранённая — одна и та же строка,
поэтому флага `isOptimistic` в проекте нет.

### Prefix invalidation (инвалидация по префиксу)
**Простое.** Сбросить всю ветку кеша одним движением.
**Техническое.** Совпадение по началу массива-ключа.
**В Veylo.** Ради этого существуют корни `["for-you"]`, `["notifications"]`,
`["comments"]`, `["profile"]` в `queryKeys.ts`. Пример из комментария к коду: список
уведомлений и счётчик непрочитанных сбрасываются вместе — «две проекции одной таблицы,
и они не должны расходиться».

### `queryKey`
**Простое.** Адрес полки в кеше.
**Техническое.** Сериализуемый массив, однозначно определяющий запись.
**В Veylo.** **Единственное место, где ключ пишется буквами**, —
`src/services/queryClient/queryKeys.ts`. Ключи отдаются функциями, а не константами,
чтобы вызывающий не смог мутировать ключ, которым уже адресована живая запись.

### `removeQueries`
**Простое.** Выкинуть запись, а не пометить устаревшей.
**Техническое.** Удаление записи из кеша целиком.
**В Veylo.** Там, где данных больше не существует, а не «они старые»:
`useDeleteBoard.ts`, `useDeleteTodo.ts`, `useUpdateProfile.ts`, `useTodoDrop.ts`.

### Rollback (откат)
**Простое.** Вернуть как было, если сервер отказал.
**Техническое.** Восстановление снимка кеша в `onError`.
**В Veylo.** Работает **только потому**, что функции `apply*` не мутируют вход.
`onMutate` снимает снимок массива, а кеш держит те же самые объекты — переномеровка
«на месте» не оставила бы `onError` ничего для восстановления. Это записано в
`services/todos/cache.ts` как причина, а не как стиль.

### `setQueryData`
**Простое.** Положить данные в кеш руками.
**Техническое.** Прямая запись значения по ключу.
**В Veylo.** Так работает почти каждая мутация доски — вместо инвалидации. Что именно
пишется, решают чистые функции `(rows, …) => rows` из `services/todos/cache.ts` и
`services/columns/cache.ts`.

### `staleTime`
**Простое.** Сколько данные считаются свежими.
**Техническое.** Время, в течение которого повторный запрос не отправляется.
**В Veylo.** `30_000` — 30 секунд, `queryClient.ts:111`. Смысл: переключение вкладки
браузера не должно быть перезагрузкой доски.

### `staleTime` vs `gcTime`
**Простое.** «Когда перечитать» против «когда забыть».
**Техническое.** `staleTime` — про свежесть активных данных; `gcTime` — про время жизни
**неиспользуемых**.
**В Veylo.** 30 секунд против 10 минут. Ушёл с доски и вернулся через пять минут —
данные покажутся мгновенно (не собраны мусором) и тут же обновятся (устарели).

### Retry policy (политика повтора)
**Простое.** Что повторять при ошибке, а что бессмысленно.
**Техническое.** Предикат, решающий, повторять ли неудавшийся запрос.
**В Veylo.** `src/services/queryClient/retryPolicy.ts` + `retryPolicy.test.ts`. Читает
**две** формы ошибки, потому что ошибка PostgREST несёт `code` и **не несёт**
HTTP-статуса — без этого отказ RLS повторялся бы трижды, прежде чем показаться
пользователю.

## C · Supabase и PostgreSQL

### `check` (ограничение-проверка)
**Простое.** Правило «сюда можно только такие значения».
**Техническое.** Булево выражение, проверяемое при записи строки.
**В Veylo.** `columns.category in ('todo','in_progress','done')`,
`todos.type in ('Bug','Task','Story','Feature')`,
`boards.key_prefix ~ '^[A-Z][A-Z0-9]{1,9}$'`,
`todos_date_range_check` (`start_date <= due_date`). В TypeScript-типы **не
переносятся** — компилятор видит `string`.

### Composite foreign key (составной внешний ключ)
**Простое.** Ссылка сразу по двум колонкам, а не по одной.
**Техническое.** FK на кортеж, требующий уникального индекса на цели.
**В Veylo.** `todos (column_id, board_id) → columns (id, board_id)`. Делает
невозможным состояние «задача доски A лежит в колонке доски B» — строка, которая не
видна ни в одном интерфейсе. Ради него в `columns` есть формально избыточный
`unique (id, board_id)`. Разбор — [глава 07](07-database.md).

### `double precision`
**Простое.** Дробное число.
**Техническое.** 64-битное число с плавающей точкой, 53 бита мантиссы.
**В Veylo.** Тип колонок `rank`. Мантисса и определяет предел: примерно 50 подряд
идущих делений одной щели пополам — и середина совпадает с краем.

### Echo suppression (подавление эха)
**Простое.** Не применять к себе новость о том, что сделал сам.
**Техническое.** Отбрасывание собственного realtime-события.
**В Veylo.** `src/services/realtime/events.ts` — **одна строка правила**: INSERT,
чей `id` уже есть в кеше, не применяется. Второго механизма нет — ни заголовка
происхождения, ни списка ожидающих записей. Работает потому, что `id` минтит клиент.
Побочный бонус: повторно доставленный *чужой* INSERT идемпотентен.

### Expand → backfill → contract
**Простое.** Сначала добавь новое, потом наполни, и только потом убери старое.
**Техническое.** Трёхшаговая последовательность изменения схемы без простоя, по
миграции на шаг.
**В Veylo.** Правило записано в `docs/IMPLEMENTATION_PLAN.md` (строки 220–221, 383):
backfill — только **после** того, как expand развёрнут и проверен; приложение
разворачивается между backfill и contract. Шаги никогда не объединяются в одну миграцию.

### Forward-only migration (только вперёд)
**Простое.** Отката нет — есть следующая миграция.
**Техническое.** Отсутствие `down`-скриптов; обратное изменение пишется как новое.
**В Veylo.** 58 файлов в `supabase/migrations/`, ни одного `down`. Откат описывается
**комментарием** внутри миграции — см. секцию «Rollback» в
`20260814100000_board_key_prefix.sql`, где отдельно отмечено, с какого момента откат
перестанет быть бесплатным.

### `jsonb`
**Простое.** Произвольный объект в одной колонке.
**Техническое.** Двоичный JSON с индексируемой структурой.
**В Veylo.** `activities.payload` и `notifications.payload`, обе `not null default '{}'`.
Назначение payload записано в комментарии к колонке: «достаточно снимка, чтобы
отрисовать запись, не джойня то, что могло быть удалено — заголовки, ключи и названия
ролей, а не одни идентификаторы».

### Migration (миграция)
**Простое.** Пронумерованный шаг изменения схемы.
**Техническое.** SQL-файл, применяемый ровно один раз и в порядке имени.
**В Veylo.** 58 штук. Только через CLI (`npm run db:diff`, `npm run db:push`) —
правило из `CLAUDE.md`: *«изменение, сделанное в дашборде, — это изменение, которого
не существует»*.

### `ON CONFLICT`
**Простое.** «Если такая строка уже есть — обнови её».
**Техническое.** Условие upsert-а в `INSERT`.
**В Veylo.** Через него PostgREST реализует upsert — и отсюда ловушка, которую
обрабатывает `assign_todo_board_key`: `BEFORE INSERT`-триггер срабатывает **раньше**,
чем обнаружен конфликт.

### `on delete cascade` / `set null` / `restrict`
**Простое.** «Забрать с собой» / «оставить, но забыть ссылку» / «сначала разберись».
**Техническое.** Реакция внешнего ключа на удаление родителя.
**В Veylo.** Все три и каждая осмысленно: `cascade` на содержимом доски,
`set null` на `todos.creator_id` и `assignee_id` (задача переживает автора),
единственный `restrict` — `todos.column_id` (удалить непустую колонку база не даст).

### Partial index (частичный индекс)
**Простое.** Оглавление только для нужных строк.
**Техническое.** Индекс с `WHERE`, покрывающий подмножество таблицы.
**В Veylo.** `notifications_user_unread_idx on notifications (user_id) where read_at is null`.
Счётчик непрочитанных читается постоянно, а прочитанные со временем составляют почти
всю таблицу — и в индекс не попадают. Индекс остаётся маленьким навсегда.

### Expression index (индекс по выражению)
**Простое.** Оглавление не по колонке, а по её преобразованию.
**Техническое.** Индекс, построенный на функции от колонок.
**В Veylo.** `profiles_username_lower_key on profiles (lower(username))` — уникальность
без учёта регистра. Индекс по самой колонке считал бы `Neo` и `neo` разными людьми.

### PostgREST
**Простое.** Переводчик, делающий из таблицы HTTP-адрес.
**Техническое.** Сервер, отображающий схему PostgreSQL в REST-API.
**В Veylo.** Всё, что идёт через `supabase.from(...)`. Важно: RLS-предикат подставляет
**PostgreSQL**, а не PostgREST, — его нельзя отключить параметром запроса, потому что
он не часть запроса.

### Presence (присутствие)
**Простое.** Аватарки тех, кто сейчас смотрит на доску.
**Техническое.** Состояние, синхронизируемое участниками канала, без хранения в БД.
**В Veylo.** `src/services/realtime/presence.ts`. Ни таблицы, ни ключа запроса, ни пути
записи. Ключ присутствия — id пользователя, поэтому две вкладки одного человека
схлопываются в одну запись. **Себя список включает** — и это записано как исправленный
баг: первая версия себя отфильтровывала, из-за чего вдвоём на доске каждый видел ровно
одну аватарку и оба выглядели сломанными.

### Publication (публикация)
**Простое.** Список таблиц, о которых Postgres рассказывает вслух.
**Техническое.** Набор таблиц логической репликации.
**В Veylo.** `supabase_realtime`, миграции `20260818090000_realtime_publication.sql` и
`20260818110000_realtime_comments.sql`. Наличие таблицы **не** делает её реплицируемой —
её нужно добавить в публикацию.

### Realtime (`postgres_changes`)
**Простое.** Сервер сам сообщает об изменении.
**Техническое.** События WAL, доставляемые по WebSocket.
**В Veylo.** `src/services/realtime/useBoardRealtime.ts` — `todos`, `columns`,
`comments`. **Ничего не перезапрашивает**: payload несёт всю строку, а обработчик
вызывает те же `apply*`, что и мутации.

### `REPLICA IDENTITY`
**Простое.** Сколько от удалённой строки попадёт в уведомление.
**Техническое.** Настройка полноты `old` в событиях репликации.
**В Veylo.** `DEFAULT` — поэтому DELETE несёт **только первичный ключ**. Прямое
следствие в коде: `RowChange.old` объявлен как `Partial<T>`, а
`queryKeys.commentThreads()` существует ровно затем, чтобы *найти* тред удалённого
комментария, который по строке узнать невозможно.

### RPC
**Простое.** Вызов функции на сервере вместо запроса к таблице.
**Техническое.** `POST` на `/rest/v1/rpc/<name>`, исполняющий SQL-функцию.
**В Veylo.** 28 собственных функций в схеме `public` (плюс служебная `graphql`), от
`accept_invite` и `provision_new_user` до `rebalance_column_ranks`. Полный список — в
блоке `Functions` файла `src/types/database.ts`.

### Sequence vs счётчик в строке
**Простое.** Общая нумерация против нумерации внутри доски.
**Техническое.** `sequence` — глобальный генератор; счётчик в колонке нумерует в
пределах родителя.
**В Veylo.** `boards.next_key` — именно счётчик: KAN-1 существует на **каждой** доске
отдельно. Sequence дал бы сквозную нумерацию по всем доскам.

### Shadow database (теневая база)
**Простое.** Пустая копия базы, чтобы понять, чем отличается настоящая.
**Техническое.** Временная БД, куда CLI накатывает миграции для диффа.
**В Veylo.** Поэтому `db:pull`, `db:diff` и `db:dump` **требуют запущенного Docker
Desktop**, а `db:push` и `db:types` — нет.

### Storage (хранилище)
**Простое.** Файлы, но с теми же правилами доступа, что и у таблиц.
**Техническое.** Объектное хранилище с политиками поверх бакетов.
**В Veylo.** Один бакет `avatars`, `src/services/profile/uploadAvatars.ts`, права —
миграция `20260814101000_avatar_storage_ownership.sql`.

### Tier A / Tier B (миграции)
**Простое.** Пометка «эту можно катить спокойно» или «здесь думай».
**Техническое.** Классификация риска в шапке миграции.
**В Veylo.** Первая строка почти каждого файла: `-- M14 · Per-board task key prefix.
SAFE. Tier A.`, `-- M3-14 · Membership mutation RPCs. HIGH RISK. Tier A.` Риск и tier —
**две разные оси**, они указываются вместе.

### `timestamptz`
**Простое.** Момент времени, знающий про часовые пояса.
**Техническое.** Timestamp с зоной, хранится в UTC.
**В Veylo.** Все `created_at` / `updated_at`, и — что важно для таймлайна —
`todos.start_date` и `todos.due_date` тоже `timestamptz`, **не** `date`.

### Trigger (триггер): `BEFORE` / `AFTER`
**Простое.** Секретарь, который штампует бумагу при приёме или после подшивки.
**Техническое.** `BEFORE` может изменить `NEW` до записи; `AFTER` видит уже
зафиксированную строку.
**В Veylo.** 16 триггеров. `BEFORE`: `todos_assign_board_key` (выдаёт номер),
`set_updated_at` на пяти таблицах, триггеры-инварианты. `AFTER`:
`boards_add_owner_membership`, журналы `log_*_activity`, уведомления.

### Trigger `WHEN`
**Простое.** «Просыпайся только на этот переход».
**Техническое.** Условие, при котором триггер вообще вызывается.
**В Veylo.** `on_auth_user_confirmed`:
`when (old.email_confirmed_at is null and new.email_confirmed_at is not null)` — ловит
ровно момент подтверждения почты. Рядом — `todos_notify_assignment` с
`after insert or update **of assignee_id**`: переименование задачи его не будит.

### Upsert
**Простое.** «Вставь или обнови».
**Техническое.** Вставка с обработкой конфликта по ключу.
**В Veylo.** `addTodo` делает upsert, а не insert: гонка с `reorderTodos` не должна
оставить полузаписанную строку.

## D · Безопасность

### `accessible_board_ids()`
**Простое.** «Список досок, куда мне вообще можно».
**Техническое.** `SECURITY DEFINER STABLE`-функция, возвращающая множество id.
**В Veylo.** **Точка расширения всей модели прав.** Каждая политика на `columns`,
`todos` и `comments` — это `board_id in (select public.accessible_board_ids())`. M3
расширил доступ с владельца на членство, поменяв **одну функцию**, не тронув ни одной
политики.

### `anon` / publishable key
**Простое.** Ключ, который можно показывать.
**Техническое.** Публичный ключ проекта, идентифицирующий его, но не дающий прав.
**В Veylo.** `VITE_SUPABASE_PUBLISHABLE_KEY`. Виден в бандле, и это нормально — права
выдаёт JWT пользователя через RLS.

### `auth.uid()`
**Простое.** «Кто спрашивает».
**Техническое.** Функция, возвращающая id пользователя из JWT текущего запроса.
**В Veylo.** Пишется как `(select auth.uid())` — см. InitPlan. У `todos.creator_id`
**нет** дефолта `auth.uid()`, поэтому `addTodo` передаёт его явно.

### `board_role()` / `board_role_rank()`
**Простое.** «Кто я на этой доске и насколько это много».
**Техническое.** Helper-функции, возвращающие роль и её числовой ранг.
**В Veylo.** Ранг зеркалится на клиенте в `src/services/members/permissions.ts`
(`viewer 1 < editor 2 < admin 3 < owner 4`) — и зеркалится **намеренно**, чтобы UI
предлагал ровно те действия, которые пройдут на сервере.

### Defense in depth (эшелонированная защита)
**Простое.** Два разных замка на разные случаи.
**Техническое.** Дублирование контроля на независимых уровнях.
**В Veylo.** Правило из code review checklist: запрос фильтруется и на клиенте
(`.eq("board_id", …)`), и в RLS. Клиентский фильтр — **корректность** («хочу именно эту
доску») и попадание в индекс; политика — **безопасность**. Показательно обратное:
`notificationsApi.ts` **не** добавляет `.eq("user_id", …)`, потому что «мои
уведомления» — это и есть политика, а второе определение «моего» могло бы с ней
разойтись.

### `grant` / `revoke`
**Простое.** Выдать и отобрать право на действие с таблицей.
**Техническое.** Привилегии SQL, отдельные от RLS и проверяемые **до** политик.
**В Veylo.** Именно так `activities` и `notifications` сделаны «только для триггеров»:
INSERT-гранта нет вообще. Комментарий к `notifications`: *«trigger-written only: there
is no insert grant, which is what makes an entry evidence rather than a claim»*.

### InitPlan
**Простое.** Вычислить один раз на запрос, а не на каждую строку.
**Техническое.** Узел плана PostgreSQL для подзапроса, не зависящего от строки.
**В Veylo.** Причина, по которой в политиках пишется `(select auth.uid())`, а не
`auth.uid()`: обёртка в подзапрос заставляет планировщик посчитать значение **один раз
на запрос**. Обосновано в шапках как минимум пяти миграций, начиная с
`20260805121441_rls_policies.sql:77`. На таблице в 10 000 строк это разница между
одним вызовом и десятью тысячами.

### JWT
**Простое.** Подписанный пропуск, который нельзя подделать.
**Техническое.** JSON Web Token: заголовок, payload, подпись.
**В Veylo.** Выдаёт GoTrue, `supabase-js` кладёт в `localStorage` и прикладывает к
каждому запросу; `auth.uid()` в базе читает именно его.

### Policy (политика)
**Простое.** Правило на полке, а не на входной двери.
**Техническое.** Правило RLS для конкретной таблицы, роли и команды.
**В Veylo.** Именованные и переприменяемые: каждая миграция сперва
`drop policy if exists`, потом `create policy` — чтобы файл можно было накатить
повторно.

### Refresh token
**Простое.** Второй ключ, которым молча продлевают сессию.
**Техническое.** Долгоживущий токен для получения нового access-токена.
**В Veylo.** Обрабатывается `supabase-js` по умолчанию; приложение его не трогает.
Единственные упоминания в репозитории — **выключение** автообновления в тестовой
обвязке: `autoRefreshToken: false` в `src/services/auth/username.live.test.ts` (строки
42 и 90). Деталей ротации репозиторий не фиксирует — *Repository evidence is
insufficient to determine this.*

### RLS (Row Level Security)
**Простое.** Охранник у каждой полки, а не у входа в здание.
**Техническое.** Предикат, который PostgreSQL добавляет к каждому запросу к таблице.
**В Veylo.** Включена на всех прикладных таблицах. Граница безопасности проходит здесь,
а не в React и не в API-слое. Полностью — [глава 08](08-security.md).

### `search_path`
**Простое.** Список мест, где функция ищет таблицу по короткому имени.
**Техническое.** Порядок разрешения имён схем.
**В Veylo.** `set search_path = ''` в каждой SQL-функции — и это защита от эскалации:
без неё пользователь мог бы создать свою `myschema.profiles`, поставить схему первой, и
`SECURITY DEFINER`-функция обратилась бы к подложной таблице **с правами владельца**.
Пустой путь заставляет писать `public.profiles` целиком.

### `SECURITY DEFINER` / `SECURITY INVOKER`
**Простое.** Функция работает от имени автора / от имени вызывающего.
**Техническое.** `DEFINER` исполняется с правами владельца и **обходит RLS**;
`INVOKER` (по умолчанию) — с правами вызывающего.
**В Veylo.** `DEFINER` там, где нужно ответить на вопрос, ответ на который сам по себе
закрыт политикой (`accessible_board_ids`, `board_roster`). Цена: такая функция обязана
проверять права **сама**, и в конце миграции идёт `revoke ... from public, anon`.

### `service_role` key
**Простое.** Мастер-ключ, открывающий всё.
**Техническое.** Ключ, **обходящий RLS** целиком.
**В Veylo.** В клиентском коде не появляется никогда. Live-тесты достают его через
Supabase CLI в момент запуска и передают **без** префикса `VITE_`, поэтому он физически
не может попасть в бандл (`vitest.live.config.ts`).

### `USING` vs `WITH CHECK`
**Простое.** «Какие строки я вижу» против «какие строки мне можно записать».
**Техническое.** `USING` фильтрует существующие строки (SELECT/UPDATE/DELETE),
`WITH CHECK` проверяет строку **после** изменения (INSERT/UPDATE).
**В Veylo.** У UPDATE-политик обычно оба: `using` не даёт трогать чужое, `with check` —
превратить своё в чужое. Например, политика на `spaces`: `using (owner_id = auth.uid())`
и такой же `with check` — иначе владелец мог бы переписать `owner_id` на другого.

### Триггер как инвариант
**Простое.** Правило, которое нельзя обойти, зайдя с другой стороны.
**Техническое.** Ограничение, реализованное на таблице, а не в вызывающем коде.
**В Veylo.** Пара `boards_add_owner_membership` (создаёт членство владельца) +
`board_members_owner_immutable` (не даёт его удалить или понизить) вместе держат
инвариант «у доски всегда ровно один владелец, и он всегда в `board_members`».
Логика в одной функции защищала бы один путь записи; триггер — все.

## E · Домен Veylo

### Activity (событие истории)
**Простое.** Строчка в журнале «кто что сделал».
**Техническое.** Строка `activities`, пишется только триггером.
**В Veylo.** `check` на **паре** `(entity_type, action)` — 11 допустимых сочетаний.
У `entity_id` **нет** внешнего ключа намеренно: запись должна объяснять себя и после
удаления того, о чём рассказывает.

### Assignee (исполнитель)
**Простое.** На ком задача.
**Техническое.** `todos.assignee_id → profiles(id) on delete set null`.
**В Veylo.** Его изменение — единственное, что будит `todos_notify_assignment`
(`update of assignee_id`).

### Board (доска)
**Простое.** Рабочее пространство с колонками и карточками.
**Техническое.** Строка `boards`; **единица владения** всей модели.
**В Veylo.** `columns.board_id` и `todos.board_id` — `NOT NULL` с внешними ключами.
Маршрут `/boards/:boardId`, параметр читает `src/hooks/useBoardId.ts`.

### `board_key` / task key (ключ задачи)
**Простое.** Номер вида `KAN-12`, который можно вставить в переписку.
**Техническое.** Счётчик, уникальный в пределах доски: `unique (board_id, board_key)`.
**В Veylo.** Выдаёт триггер `assign_todo_board_key` из `boards.next_key`, **не** id
строки. Номера **не переиспользуются**: удалили KAN-2 — следующая всё равно KAN-4.
Пока карточка в полёте, `board_key` равен `null`, и это и есть состояние «ещё не
сохранена». Отрисовка — `src/utils/taskKey.ts`.

### Category (категория колонки)
**Простое.** Смысл колонки: «к работе», «в работе», «готово».
**Техническое.** `columns.category` — `check` из трёх значений.
**В Veylo.** Из неё **выводится** «сделано» — колонки `todos.completed` больше нет.
Палитра категорий лежит не в БД, а в `src/constants/columns.ts`: цвет — это
представление, перекраска должна быть правкой, а не миграцией. `categoryOf()` падает в
`todo`, поэтому строка с `null` всё равно рисуется.

### Column (колонка)
**Простое.** Вертикальный список на доске.
**Техническое.** Строка `columns`, порядок — по `rank`.
**В Veylo.** Всё, что колонка умеет, живёт в `src/components/columns/`. Свёрнутость
колонки — состояние **только клиента**, в БД не сохраняется.

### Column limit (лимит колонки)
**Простое.** Мягкое предупреждение «здесь слишком много».
**Техническое.** `min_limit` / `max_limit`, оба nullable.
**В Veylo.** **Совещательные**: ни `onDragEnd`, ни `useTodoDrop` их не спрашивают,
дроп они не блокируют. `limitBreach()` (`src/services/columns/limitBreach.ts`)
превращает нарушение в текст предупреждения, и текст живёт в `aria-label` заголовка,
а не в тексте DOM.

### Comment (комментарий)
**Простое.** Сообщение под задачей.
**Техническое.** Строка `comments` с составным FK на `(todo_id, board_id)`.
**В Veylo.** `author_id` — `cascade` (в отличие от `todos.creator_id` с `set null`):
комментарий — это **слова автора**, а не пометка на чужой строке. Пустой запрещён на
уровне БД: `check (length(btrim(content)) > 0)`.

### Creator (автор)
**Простое.** Кто завёл задачу.
**Техническое.** `todos.creator_id → profiles(id) on delete set null`.
**В Veylo.** Пережиток осмысленный: `user_id` из `todos` удалён в M2, авторство
осталось как `creator_id`. Дефолта `auth.uid()` у колонки нет — `addTodo` шлёт значение
явно.

### Dense position (плотная позиция)
**Простое.** Нумерация «первый, второй, третий».
**Техническое.** Целочисленный индекс, требующий переномерации соседей при вставке.
**В Veylo.** Колонка `position` ещё существует как лениво обновляемое зеркало, но
**порядок по ней никто не читает**, кроме резервной ветки в `byRank`. Историческая
причина замены: переномерация писала весь массив, и два одновременных драга
перезаписывали карточки, которых никто не трогал.

### For You (лента «Для тебя»)
**Простое.** Личная страница: что моё, через все доски.
**Техническое.** Набор запросов без фильтра по доске — фильтром служит сама RLS.
**В Veylo.** `src/services/forYou/`, ключи под корнем `["for-you"]`. **Вкладки
«Starred» нет** — её собрали и убрали: звезда требует таблицы `todo_stars`, миграция
которой так и не была применена. Причина записана в шапке
`src/services/forYou/feed.ts:14`.

### Invite (приглашение)
**Простое.** Ссылка, по которой человек попадает в доску.
**Техническое.** Строка `board_invites`; **токен и есть пропуск**.
**В Veylo.** Пишется только через RPC (`create_invite`, `accept_invite`,
`decline_invite`) — клиентской политики на запись нет. Роль `'owner'` в приглашении
запрещена `check`-ом. Принятое приглашение **не удаляется** (проставляется
`accepted_at`); удаление строки означает **отзыв**.

### Member / Role (участник и роль)
**Простое.** Кто в доске и что ему можно.
**Техническое.** Строка `board_members` с составным первичным ключом
`(board_id, user_id)`.
**В Veylo.** Составной PK делает состояние «две роли у одного человека на одной доске»
**непредставимым**. Клиентское зеркало матрицы прав —
`src/services/members/permissions.ts`, и там прямо написано: *«This is UX and never
enforcement»*.

### Notification (уведомление)
**Простое.** Колокольчик.
**Техническое.** Строка `notifications`, только для получателя, пишется триггером.
**В Veylo.** Два типа: `'invite'` и `'assigned'` (`check` в БД, union-тип
`NotificationType` в `src/services/notifications/notifications.ts:16`). Прочитанность —
**`read_at timestamptz`, а не `is_read boolean`**: одна колонка отвечает и «прочитано
ли», и «когда».

### Presence stack
**Простое.** Стопка аватарок «кто сейчас здесь».
**Техническое.** Отрисовка присутствия из канала.
**В Veylo.** `PresenceStack`, данные — из `src/services/realtime/presence.ts`. Ничего
не хранится: закрыл вкладку — исчез.

### Rank (дробный ранг)
**Простое.** Место в очереди, заданное числом между соседями.
**Техническое.** `double precision`-ключ сортировки, а не порядковый номер.
**В Veylo.** `src/utils/rank.ts`. `RANK_GAP = 1024` — не 1: запас на десять вставок
в середину, прежде чем дробная часть вообще начнёт есть мантиссу. Значение совпадает
с множителем в `20260814121000_backfill_ranks.sql`, и совпадать **обязано**.

### `rankBetween`
**Простое.** «Дай число строго между этими двумя».
**Техническое.** Чистая функция, возвращающая `null` при исчерпании точности.
**В Veylo.** `null` — **не ошибка**, а сигнал «перебалансируй колонку и повтори»
(`rebalanceColumnRanks` / `rebalanceBoardColumnRanks`). Дроп в самый верх делит
`after / 2`, а не вычитает `RANK_GAP`, — иначе колонка, в начало которой всё время
что-то кладут, ушла бы в отрицательные числа.

### `byRank`
**Простое.** Сравнение, по которому сортируется всё.
**Техническое.** Компаратор с откатом на `position * RANK_GAP` при отсутствии ранга.
**В Veylo.** Откат делает **порядок развёртывания неважным**: строка, записанная старым
клиентом, встаёт туда, куда должна, — fallback считает ровно то, что записал бы
backfill.

### Space (пространство)
**Простое.** Папка для досок.
**Техническое.** Строка `spaces`; `boards.space_id` — nullable, `on delete set null`.
**В Veylo.** **Не является областью прав** — это записано в комментарии к таблице
заглавными по смыслу: *«NOT a permission scope … `boards.space_id` grants nothing»*.
Удаление папки не удаляет доски, они просто перестают быть разложенными.

### Unfiled → «My Space»
**Простое.** Как раньше называлась папка по умолчанию.
**Техническое.** Переименование данных миграцией.
**В Veylo.** `20260824120000_default_space_name.sql` переименовывает все пространства с
названием `unfiled` (без учёта регистра и пробелов) в **`My Space`** и логирует число
затронутых строк через `raise notice`. То есть «Unfiled» — **исторический** термин,
в текущем интерфейсе его нет.

### Todo / work item (задача)
**Простое.** Карточка.
**Техническое.** Строка `todos`, 20 колонок.
**В Veylo.** `id` минтит **клиент**. В коде и в UI встречаются оба слова — «todo» в
именах модулей и таблиц, «work item» в комментариях и текстах.

### Viewed (просмотренное)
**Простое.** «Что я недавно открывал».
**Техническое.** Список id, хранимый на устройстве.
**В Veylo.** `src/services/forYou/viewed.ts` (+ `viewed.test.ts`), хранение — в
`localStorage`. Разрешается в задачи через `queryKeys.forYouByIds(ids)`, ключ которого
— отсортированные и склеенные id, чтобы две вкладки с одним набором делили один запрос.

## F · Инструменты

### `.env` и префикс `VITE_`
**Простое.** Настройки, которые Vite подставляет в код при сборке.
**Техническое.** Только переменные с префиксом `VITE_` попадают в клиентский бандл.
**В Veylo.** Нужны `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`; файл в
`.gitignore`. `src/services/api/supabase.ts` **бросает на уровне модуля**, если чего-то
нет. Важное следствие: значения инлайнятся при сборке — забытая переменная лечится
**пересборкой**, а не передеплоем. И зеркальное следствие: отсутствие префикса — это
то, что не пускает `service_role` в бандл.

### `@dnd-kit/core`
**Простое.** Библиотека перетаскивания.
**Техническое.** Сенсоры, droppable/draggable, определение попадания, overlay.
**В Veylo.** Взят **только `core`**. `@dnd-kit/sortable` не используется: сортируемый
список сам переставляет элементы во время драга, а доска Veylo не шевелится — двигается
только `DragOverlay`.

### ESLint
**Простое.** Проверка стиля и типичных ошибок.
**Техническое.** Статический анализатор с правилами.
**В Veylo.** `npm run lint` → `eslint .`.

### Live test (живой тест)
**Простое.** Тест, который ходит в настоящую базу.
**Техническое.** Набор, требующий реальных учётных данных и отдельного конфига.
**В Veylo.** Ровно один файл: `src/services/auth/username.live.test.ts`, конфиг —
`vitest.live.config.ts`, который добывает `service_role` через Supabase CLI на старте.
Остальные 46 файлов `*.test.ts` — чистая логика без сети.

### Prettier + `prettier-plugin-tailwindcss`
**Простое.** Автоформатирование, включая порядок классов Tailwind.
**Техническое.** Форматтер с плагином, сортирующим утилиты в каноническом порядке.
**В Veylo.** Скрипта нет — вызывается как `npx prettier --write src/...`.

### React Compiler
**Простое.** Автоматическая мемоизация без `useMemo` руками.
**Техническое.** Компилятор, вставляющий мемоизацию на этапе сборки.
**В Veylo.** **Выключен, плагин удалён** — и это измеренное решение, а не вкус: 2.7×
времени сборки и +25 % к чанку доски против неизмеренной выгоды. Причина записана в
`vite.config.ts`; триггер к пересмотру — M9-05.

### Supabase CLI
**Простое.** Инструмент, через который меняется схема.
**Техническое.** Локальный клиент к проекту Supabase: диффы, применение, типы.
**В Veylo.** `npm run db:diff` / `db:push` / `db:pull` / `db:types`. Первым трём (кроме
push) нужен Docker. Привязанный проект — `nxnnfaoyttbzndphnawe`, и **PITR на нём не
включён**: точки восстановления для неудачной миграции данных нет.

### Tailwind v4 (CSS-first)
**Простое.** Стили настраиваются в CSS, а не в JS-конфиге.
**Техническое.** Конфигурация через директивы в таблице стилей.
**В Veylo.** `tailwind.config` **отсутствует**; всё в `src/styles/global.css` —
`@custom-variant`, `@theme inline` и токены.

### `tsc -b`
**Простое.** Единственная настоящая проверка типов.
**Техническое.** Сборка проекта TypeScript по ссылкам между конфигами.
**В Veylo.** Часть `npm run build`. Дев-сервер типы **не проверяет**, поэтому
`npm run build` — то, что надо запустить, прежде чем говорить «компилируется».
Включены `noUnusedLocals` / `noUnusedParameters`: неиспользованный импорт роняет сборку.
Тестовые файлы из `tsconfig.app.json` **не исключены** — тест, разошедшийся с типами
своего предмета, ломает сборку, а не только прогон.

### Vite
**Простое.** Дев-сервер и сборщик.
**Техническое.** Бандлер на ES-модулях с быстрым HMR.
**В Veylo.** `npm run dev`, `npm run build`, `npm run preview`.

### Vitest
**Простое.** Запускалка тестов.
**Техническое.** Тест-раннер с API в стиле Jest.
**В Veylo.** **Единственный механизм тестирования** — самопроверки `*.check.ts` на
`node --experimental-strip-types` удалены и перенесены в `*.test.ts`. Конфиг
`vitest.config.ts` стоит отдельно от `vite.config.ts`: тесты — чистый TypeScript, им не
нужны ни плагин React, ни Tailwind. **React Testing Library нет намеренно**: риск живёт
в чистой логике, а компонентные тесты, которые никому не нужны, — это стоимость
поддержки.

### shadcn/ui (вендоренные примитивы)
**Простое.** Компоненты, скопированные в проект, а не установленные пакетом.
**Техническое.** Исходники в репозитории, поверх `radix-ui` и `@base-ui/react`.
**В Veylo.** `src/components/ui/`. Алиасы в `components.json` настроены верно, поэтому
`npx shadcn add` кладёт файл в `ui/` с импортом `@/utils/cn`. Отдельно:
`src/components/ui/SideBarUI/` — это **сайдбар**, а не UI-кит: там только `sidebar.tsx`
и `use-sidebar.ts`.
